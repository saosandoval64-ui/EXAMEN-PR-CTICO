Cómo se hizo

Documentación del proceso de desarrollo de Libroteca.

01

El planteamiento del examen

Lo que pidió la universidad

El examen práctico de Desarrollo de Aplicaciones Web (Tecnológico Universitario Espíritu Santo) pidió construir una aplicación web para gestionar una biblioteca de libros usando Flask, SQLite y una API RESTful con Flask-RESTful, y subirla a GitHub con un README.

✓ Listado de libros (título, autor, género, año)
✓ Búsqueda por título, autor o género
✓ Agregar libros
✓ Actualizar libros
✓ Eliminar libros
✓ GET /api/books
✓ GET /api/books/<id>
✓ POST /api/books
✓ PUT /api/books/<id>
✓ DELETE /api/books/<id>
✓ Base de datos SQLite funcional
✓ README en GitHub + repositorio subido
02

Tecnologías

El stack elegido

Python 3 Flask Flask-RESTful SQLite Jinja2 HTML5 CSS3 JavaScript Git & GitHub

SQLite no necesita ningún conector extra: el módulo sqlite3 viene integrado en Python. La interfaz se maquetó con plantillas Jinja2 y CSS propio, sin frameworks externos.

03

Los pasos seguidos

Proceso de implementación

  1. Entorno de trabajo: se creó un entorno virtual e instalaron Flask y Flask-RESTful desde requirements.txt.
  2. Estructura del proyecto: app.py, models.py, routes.py, api.py, templates/, static/ y database.db.
  3. Modelo y base de datos: tabla libros con id autoincremental, título, autor, género y año de publicación (a la que añadimos descripción y portada).
  4. Rutas web: listar, buscar, agregar, editar y eliminar libros con mensajes de confirmación.
  5. Plantillas HTML: catálogo con tarjetas, formularios con validación y ficha de detalle por libro.
  6. API RESTful: recursos BookListResource y BookResource con Flask-RESTful, con códigos de estado HTTP correctos (200, 201, 400, 404).
  7. Pruebas: se probaron todos los endpoints con curl y el flujo completo desde la interfaz web.
  8. Entrega: repositorio Git, README con instrucciones y esta documentación.
04

Decisiones que se agregaron

Más allá de lo pedido

Botón «Me gusta» en cada libro

Un corazón en cada tarjeta y en la ficha de detalle marca el libro como favorito con un solo clic (POST), sin recargar decisiones. El catálogo muestra cuántos libros te gustan y el botón recuerda el estado.

Ficha de detalle con clic

Al hacer clic en una tarjeta se abre una ficha con la portada en grande y un texto explicando el libro. La descripción hace el catálogo más útil y realista.

Portadas de los libros

Cada libro puede tener imagen: se sube un archivo desde la computadora (guardado en static/uploads/) o se pega una URL. Si no hay imagen, se genera una portada automática.

Portadas en los datos de ejemplo

El script seed.py carga 10 libros cuyas portadas viven en static/portadas/, descargadas previamente con nombres legibles, para que el catálogo no inicie vacío y las imágenes no dependan de internet.

Validaciones y seguridad

Se validan campos obligatorios y el año (1000–3000), se restringe el formato de imágenes subidas, los nombres de archivo se aleatorizan y todos los formularios evitan inyección SQL usando consultas parametrizadas.

Experiencia de usuario

Confirmación antes de eliminar, mensajes flash de éxito/error, estados vacíos explicativos, diseño responsivo, tarjetas con buena separación y esquinas menos redondeadas de aspecto editorial.

ArchivoQué haceCómo se hizo
app.py Crea la app Flask y la pone a funcionar. Se creó la instancia app, se importaron los blueprints routes y api, y se registraron con app.register_blueprint(). También registra un filtro de Jinja que convierte el campo imagen en la dirección completa de la portada.
models.py El "puente" entre la app y la base de datos. Cada función abre y cierra su propia conexión sqlite3. Se usa row_factory = sqlite3.Row para leer filas como si fueran diccionarios y consultas parametrizadas (WHERE id = ?) para evitar inyección SQL. init_db() crea la tabla libros si no existe.
routes.py Las páginas web que ves en el navegador. Cada vista es una función con el decorador @web_bp.route(...). Las rutas que envían datos (POST) validan los campos, usan models para guardar y avisan con flash() (mensajes de éxito o error) antes de redirigir. La subida de imágenes se maneja con request.files y se guarda con nombre aleatorio en static/uploads/.
api.py Expone la API RESTful bajo /api. Se definieron dos recursos de Flask-RESTful: BookListResource (para la colección) y BookResource (para un libro). Cada método HTTP (get, post, put, delete) devuelve una tupla (datos, código HTTP) y se registran con api.add_resource().
seed.py Carga datos de ejemplo. Una lista de diccionarios con 10 libros (título, autor, género, año, descripción e ISBN para la portada). Un bucle llama a models.add_book() por cada uno, usando la API abierta de Open Library para las portadas.
templates/ Las vistas en HTML. base.html define el layout común (barra de navegación con buscador, mensajes flotantes y pie de página); el resto hereda con {% extends %}. Los formularios usan enctype="multipart/form-data" para poder subir imágenes y tienen una pequeña vista previa en JavaScript.
static/style.css Todo el diseño visual. CSS propio, sin frameworks: variables de color, grillas con grid, tarjetas tipo "librero" con portada, esquinas poco redondeadas, buen espaciado entre tarjetas y diseño responsivo para celular. Las portadas subidas quedan en static/uploads/.
06

Esquema de la base de datos

Tabla libros

CREATE TABLE IF NOT EXISTS libros (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    titulo TEXT NOT NULL,
    autor TEXT NOT NULL,
    genero TEXT NOT NULL,
    anio_publicacion INTEGER NOT NULL,
    descripcion TEXT NOT NULL DEFAULT '',
    imagen TEXT NOT NULL DEFAULT ''
);

La columna usa anio en lugar de año para evitar problemas con la letra "ñ" en SQLite.

07

La API RESTful

Qué es, para qué sirve y sus endpoints

La API es la interfaz para programadores: expone los mismos libros que ves en la web, pero en JSON (texto estructurado). Es lo que ves si haces clic en el botón API del menú o abres /api/books: no es una página bonita, son los datos.

En resumen: la web es para personas, la API es para máquinas. Un navegador necesita botones y tarjetas; un programa solo necesita datos ordenados. Ambos comparten la misma base de datos y las mismas operaciones.

Con la API, cualquier otro programa (una app móvil, un script, otro sitio web) puede hacer lo mismo que tú haces a mano en la interfaz:

  • GET → leer el catálogo completo o un solo libro.
  • POST → crear un libro nuevo.
  • PUT → actualizar los datos de un libro.
  • DELETE → eliminar un libro.

Se puede probar desde la terminal con curl http://127.0.0.1:5000/api/books, y este es uno de los puntos evaluados del examen.

Endpoints disponibles en /api:

MétodoRutaDescripciónRespuesta
GET/api/booksLista todos los libros200
GET/api/books/?q=textoBusca por título, autor, género o descripción200
GET/api/books/Obtiene un libro por su id200 / 404
POST/api/booksCrea un libro nuevo201 / 400
PUT/api/books/Actualiza un libro existente200 / 400 / 404
DELETE/api/books/Elimina un libro200 / 404
